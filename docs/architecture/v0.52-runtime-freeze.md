# v0.52 Runtime Freeze

Status: **frozen**. This document records the runtime trust architecture
that v0.52 ships. From this point forward, changes to the components
below require one of:

- a failing invariant test,
- a reproducible race,
- a security finding.

Anything else — more execution states, new backends, new authority
models, new evidence formats, additional orchestration — belongs to the
post-v0.52 backlog, not to the closure program. Convergence, not surface
area, is the goal.

## Frozen components

| Component | Where | Frozen property |
|---|---|---|
| `EffectStore` lifecycle | `internal/idempotency/` | The durable state graph (`PREPARED` → `EXECUTING` → `IN_FLIGHT` → terminal), its transitions, and the store contract are fixed. |
| `PREPARED` / `IN_FLIGHT` / `UNKNOWN` semantics | `internal/execution/dispatch.go`, `docs/spec/durable-execution-contract.md` | Pre-dispatch failure is safe `FAILED`; post-dispatch failure is `UNKNOWN`; `UNKNOWN` is caller-terminal and reconciliation-owned. |
| Fenced leases | `internal/idempotency/` | Only the lease holder (token + generation) may finalize; a stale owner cannot. |
| Cluster epochs | `internal/idempotency/`, recovery model | Recovery cannot overlap a pre-admitted old-coordinator mutation. |
| Authority generations | `internal/capability/grant.go`, `internal/authority/` | Server-resolved generation + digest enter the execution identity; caller values are overwritten. |
| Provider observations | `internal/execution/dispatch.go` | The provider's returned answer is persisted before the terminal decision; observation persistence failures become `UNKNOWN`, never `FAILED`. |
| Reconciliation state machine | `internal/reconcile/` | `UNKNOWN` stays `UNKNOWN` unless a resolver proves an outcome; readiness is supervised and observable. |
| Evidence digest recomputation | `internal/evidence/` | `sha256(EvidenceArtifact)` is recomputed by Crabedence; a handler-supplied digest is never signed. |
| Terminal receipt immutability | `internal/cli/attest.go`, `internal/evidence/` | V3 receipts bind `evidence_sha256`; V2 never carries it; terminal receipts are immutable. |
| PostgreSQL transaction model | `internal/idempotency/store.go` | Atomic `INSERT … ON CONFLICT` reservation, fencing, and finalize semantics. |
| SQLite single-host model | `internal/idempotency/sqlite*.go` | Same state graph and contract as PostgreSQL for single-host deployments. |
| `RouteDispatcher` | `internal/execution/router.go` | The single dispatch point; reads `descriptor.execution_route`, never a caller value; re-checks class/route at dispatch; fails closed on unknown routes. |
| `VerifiedCapabilityCatalog` | `nemo/kernel/kernel.ts` | Production kernels accept only catalogs minted by a passing envelope verification. |
| NEMO snapshot verification | `nemo/kernel/snapshot.ts` | SHA-256 over the exact canonical bytes; a rewritten capability with a stale digest fails closed. |
| Post-dispatch timeout separation | `internal/execution/dispatch.go` (`ExecutorTimeouts`) | Each durability stage derives its own bounded, detached context; emergency recovery never inherits an exhausted budget. |

## Frozen invariants

The architectural laws are first-class named tests. See
[capability-trust-model.md](capability-trust-model.md) for the full
table and `internal/capability/invariants_test.go`,
`internal/execution/invariants_test.go`, and
`internal/execution/concurrency_torture_test.go` for enforcement.

| ID | Law |
|---|---|
| INV-001 | A `MUTATION` can never execute through `LOCAL`. |
| INV-002 | A `CRITICAL` operation can never execute without `HIGH_ASSURANCE`. |
| INV-003 | An unrecognized capability can never reach a provider. |
| INV-004 | Caller-supplied execution class cannot influence routing. |
| INV-005 | Caller-supplied authority generation is ignored/rejected. |
| INV-006 | Post-dispatch ambiguity is never `FAILED`. |
| INV-007 | A stale lease owner cannot finalize. |
| INV-008 | Cluster recovery cannot overlap a pre-admitted old-coordinator mutation. |
| INV-009 | Terminal receipts are immutable. |
| INV-010 | The evidence signature covers the artifact digest. |
| INV-011 | A registry-policy change changes request identity. |
| INV-012 | A failed qualification cannot publish an RC. |
| INV-013 | A `LOCAL` capability can never require a grant. |
| INV-014 | Provider availability cannot modify capability security classification. |
| INV-015 | No model-generated field may determine trusted execution classification. |

## What remains open (closure work)

- typed qualification gates and the artifact v2 release object — **landed**
  (`scripts/lib/qualification-gates.sh` is the single validator; release
  admission and the standalone verifier both consume it; no gate
  semantics are derived from names),
- registry semantics and provider availability — **landed** (typed
  availability, diagnostics, runtime configuration identity),
- concurrency qualification — NEMO transport convergence and the durable
  100-way PostgreSQL single-dispatch proof are landed; deterministic
  failpoint interleavings and the standing stress gate remain,
- release provenance — artifact binding, verifier modes, registry policy
  identity, pre-publication clean room, attestation ordering, and public
  reverification are landed,
- the external CRITICAL qualification provider remains the largest
  remaining runtime item,
- the v0.52 RC identity and the full qualification matrix follow after
  those.
